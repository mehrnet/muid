MUID Specification

Technical architecture, Tehran epoch offset, numeric BigInt representation, and token security parameters.

1. Epoch & Numeric ID

Generated sequentially from the fixed Tehran epoch with 4 random digits:

  • Epoch: 2026-09-22 00:00:00 (UTC+3:30) = 1790022600 sec
  • Formula: RawBigInt = (ElapsedSec * 10000) + Random(0..9999)
  • Database: Stored as native 64-bit BIGINT
  • Vectors: 13954201234 → 6eryyky | 390889398 → 6gq46u

2. Secret & API Regex

256-bit security hash and standardized authorization token regex:

  • Secret: 32 CSPRNG bytes in Base62 (43 alphanumeric chars)
  • Token: "<account id>:<account secret>"
^[0-9a-z]{6,12}:[0-9a-zA-Z]{43}$

The Genesis Epoch Decision (Why 2026-09-22?)

Day 0 Offset

The first day of Mehr being released was 2026-09-23 (which corresponds to 2585-07-01, or 1 Mehr 2585). MUID starts exactly one day before the release date to anchor the timeline cleanly at Day 0 (which then becomes 2585-06-31 or 2026-09-22):

نخستین روز انتشار رسمی مهر، تاریخ ۲۰۲۶-۰۹-۲۳ برابر با ۲۵۸۵-۰۷-۰۱ (۱ مهر ۲۵۸۵) است. مبدا زمانی MUID دقیقا یک روز قبل آغاز می‌شود تا چرخه شناسه‌ها از روز صفر (برابر با ۲۵۸۵-۰۶-۳۱ یا ۲۰۲۶-۰۹-۲۲) پایه‌گذاری شود:

Day 0 · Genesis Epoch
2026-09-22 · 2585-06-31 (31 Shahrivar)

The timeline begins at 00:00:00 (UTC+3:30) (Unix timestamp 1790022600). Genesis state, system bootstrapping, and initial node migrations execute cleanly within this 0-indexed day without producing negative offsets.

Day 1 · Official Release
2026-09-23 · 2585-07-01 (1 Mehr)

The official release of Mehr begins. User accounts created on launch day start from Day 1 (after 86,400s), ensuring all public identifiers follow clean positive natural numbers.
